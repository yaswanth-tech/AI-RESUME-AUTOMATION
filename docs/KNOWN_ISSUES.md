# Known issues and release gates

- Resume migrations are applied to the configured Supabase database and the current schema diff is clean. One legacy ATS analysis with an invalid user reference was quarantined. Validate backup/restore and quarantine retention on the production rollout process.
- No labeled PDF/DOCX field-extraction corpus is present, so the requested field-level extraction accuracy percentage is unknown. Existing parser unit fixtures cover text, not realistic document layout variation.
- OCR was not exercised against a scanned resume in this environment. It is implemented, but requires local Tesseract language data or network access for language data retrieval; scans beyond eight pages are rejected for OCR.
- API E2E passed against Supabase with two temporary accounts that were cleaned up; it covers cross-account resume isolation. Responsive visual checks and live provider calls remain unverified because browser automation and provider credentials were not used.
- The OCR renderer dependencies are larger than the prior backend dependency set. `npm install` reported an engine warning for transitive `nanoid@6` (Node 22+ required) on the available Node 20.11.1 runtime; current tests and server startup still succeeded.
- Resume files use restrictive filesystem permissions and live outside the static root, but application-level file encryption is not implemented. Use encrypted private volumes/backups and database encryption.
- Multi-process deployments need shared private artifact storage and distributed cache/rate-limit storage. AI cache and some pre-existing practice-session state are process-local.
- The Prisma connection pool defaults to five connections per process (`DB_CONNECTION_LIMIT`). Supavisor runtime connections use transaction mode; multi-instance deployments must budget combined app-side pools against Supabase limits.
- Existing legacy career modules remain present and mounted; not all unrelated legacy models/routes have been migrated to required per-user authorization. A separate review is needed before exposing every legacy endpoint in a multi-tenant deployment.
- The local `backend/.env` file remains untouched and is not tracked in this Git worktree; `.gitignore` excludes it and permits `backend/.env.example`. Its contents were not displayed or checked. Rotate any `DATABASE_URL` password, `JWT_SECRET`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, or other credentials if they were committed/shared elsewhere.
